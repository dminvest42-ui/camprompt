# Разбор проблем CamPrompt

Для поддержки пользователя и для отладки разработчиком. Сначала — что говорит пользователь, потом — что смотреть.

Навигация: [AGENT_ONBOARDING](AGENT_ONBOARDING.md) · [ARCHITECTURE](ARCHITECTURE.md) · [DECISIONS](DECISIONS.md) · [RISKS](RISKS.md) · [CHANGELOG](../CHANGELOG.md)

---

## 1. «Не открывается», «повреждено», «неизвестный разработчик»

Приложение подписано ad-hoc, без нотарификации ([D-007](DECISIONS.md#d-007-ad-hoc-подпись--xattr-пока-нет-apple-developer)).

Порядок:
1. Приложение должно лежать **в `/Applications`**, не в «Загрузках» и не запускаться из окна `.dmg`. Это самая частая причина: карантин снят, а Gatekeeper всё равно блокирует.
2. В Терминале — и **после каждого обновления** тоже:

       xattr -dr com.apple.quarantine /Applications/CamPrompt.app

3. Запускать из `/Applications`.

Проверить состояние подписи и карантина:

    xattr -l /Applications/CamPrompt.app
    codesign -dv --verbose=4 /Applications/CamPrompt.app

## 2. Камера не включается / чёрное превью / в записи только звук

**Сначала: какая версия?** До v0.2.0 это известный баг на камерах 720p (MacBook Air M1 2020, все 13″ MacBook Pro) — [D-011](DECISIONS.md#d-011-sessionpreset-выставляется-после-добавления-входов). Лечится обновлением.

Признак именно этого случая: внешние камеры и айфоны через Continuity работают, встроенная — нет.

Дальше по порядку:
1. Системные настройки → Конфиденциальность и безопасность → Камера → CamPrompt включён.
2. Закрыть FaceTime, Zoom, Photo Booth, браузер с открытой камерой → «Включить камеру». Признак занятости в диагностике: `занята_другим=true`.
3. Камера (кнопка в тулбаре) → **«Скопировать диагностику»** → прислать текст.

### Как читать диагностику

    CamPrompt 0.2.2 · macOS Version 15.x
    Разрешения: камера=разрешено, микрофон=разрешено
    Выбрано: камера=авто, микрофон=авто

    Камеры (2):
      • FaceTime HD Camera [AVCaptureDeviceTypeBuiltInWideAngleCamera] id=...
        макс=1280×720 актив=1280×720 занята_другим=false подключена=true
      ...
    Сессия: running=true preset=High inputs=2 outputs=1
      соединение vide: active=true enabled=true
    Активный формат: FaceTime HD Camera · 1280×720 · High

| Что видно | Вывод |
|---|---|
| `разрешения: камера=запрещено` | TCC, лечится в системных настройках |
| `Камеры (0)` | Система не отдаёт ни одного устройства — перезагрузка, проверка на другом приложении |
| `занята_другим=true` | Камеру держит другое приложение |
| `inputs=1` при живой камере | Не добавился видеовход — читать «Лог последней настройки» |
| `соединение vide: active=false` | Вход есть, сигнала нет — предложить другую камеру в настройках |
| `макс=1280×720` и жалоба на старой версии | Ровно инцидент D-011 |

### Логи на Mac пользователя

Приложение пишет в унифицированный лог. Console.app → поиск по подсистеме, либо в Терминале:

    log show --predicate 'subsystem == "ru.olya.camprompt"' --last 30m --info
    log stream --predicate 'subsystem == "ru.olya.camprompt"' --info   # живым потоком

Полезные строки: `startCamera: <имя камеры>, cameras found: N`, `session running: …`, `configure failed: …`, `startRecording refused: no active video connection`.

## 3. Запись не начинается, кнопка не реагирует

- Кнопка записи в главном окне выключена, пока сессия не запущена (`disabled` при `!isSessionRunning`).
- Если видеосигнала нет, запись **намеренно** не стартует ([D-012](DECISIONS.md#d-012-отказ-входа-виден-пользователю-запись-не-стартует-без-видеосигнала)) — смотреть баннер ошибки под превью.
- Если идёт обратный отсчёт, повторное нажатие его отменяет (это не баг).

## 4. Файл записи не там, где ждали

Папка `Teleprompter` внутри Загрузок (по умолчанию), Документов или Фильмов — переключатель в настройках камеры. Быстро: Камера → «Открыть папку записей». Имя файла: `CamPrompt_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.mov`.

## 4a. Запись слишком большая / не проходит в Telegram-бота

Бот `@Karusel_Reels_Short_bot` принимает файлы до **2 ГБ**. В режиме «Максимум» это ~20 минут, в «Стандарте» ~73.

1. Камера → «Качество записи» → **Стандарт**.
2. Записать минуту, снова открыть настройки камеры: строка «Последняя запись» покажет реальный поток. В «Стандарте» ожидается ~3,5–3,8 Мбит/с.
3. Если там ~13 Мбит/с — Mac проигнорировал ограничение. В диагностике строка «Качество записи: … → …» покажет, какая ступень отката сработала ([D-020](DECISIONS.md#d-020-качество-записи-hevc-с-потолком-битрейта-и-ступенчатый-откат)); в логе `setOutputSettings rejected (...)` — какая отклонена и почему.

Программа не открывает запись → она не понимает HEVC (бывает на старом Windows). Режим «Максимум» пишет в H.264.

Монтаж на сервере не склеивает части одного урока → одна часть записана до v0.3.0 (H.264), другая после (HEVC). `concat -c copy` требует одинаковый формат: сначала перекодировать части к одному.

## 5. Панель суфлёра: не видно, не там, не тянется

| Симптом | Причина / что делать |
|---|---|
| Панель не появляется | ⌘T или кнопка справа внизу главного окна; `Esc` её прячет |
| Панель на другом мониторе | Выбирается экран с физическим вырезом (`safeAreaInsets.top > 0`), иначе главный. На мониторе без выреза панель встаёт по центру верхней кромки |
| Края не тянутся | Зона 8 точек от края; курсор должен смениться на ↔ / ↕. В режиме «под камерой» тянущийся край двигает обе стороны — панель остаётся по центру |
| Панель не двигается мышью | Перетаскивание окна работает только в свободном режиме (галочка «Крепить под камерой» снята) |
| Текст обрывается многоточием | Регресс v0.1.0 — потерян `.fixedSize(horizontal: false, vertical: true)` ([D-009](DECISIONS.md#d-009-текст--одна-text-нода-со-сдвигом-не-scrollview)) |
| Панель видна в записи экрана | Включить «Прятать от записи экрана» — ставит `sharingType = .none` |
| Панель мигает при Mission Control | Системное поведение, не лечится |

## 6. Клавиши не работают

- Хоткеи локальные: приложение должно быть активным ([RISKS](RISKS.md) §5). Глобальные — в плане ([DEV_PLAN](DEV_PLAN.md) M4).
- Пока курсор в поле ввода (текст скрипта, число в настройках, скорость на плашке) — пробел и стрелки идут в поле, а не в суфлёр. Это намеренно ([D-014](DECISIONS.md#d-014-панель-может-становиться-key-оставаясь-неактивирующей)).
- Если пробел перестал работать **вне** полей ввода — смотреть `AppState.handleKeyDown`: гард по `firstResponder` мог начать ловить лишнее.

## 7. Интерфейс тормозит

- **Поповер настроек открывается секунды** → почти наверняка вернули `step:` в `Slider` ([D-013](DECISIONS.md#d-013-шаг-ползунка--в-binding-а-не-в-sliderstep)). Проверить `NumberSliderRow`.
- **Дёргается прокрутка на длинном тексте** → см. [RISKS](RISKS.md) §3, план Б — `CVDisplayLink`.

## 8. Коммит не проходит: «gitleaks нашёл секрет»

Так и задумано — репозиторий публичный ([D-019](DECISIONS.md#d-019-публичный-репозиторий-с-барьером-на-коммите)). Что делать:

1. Посмотреть, на что сработало: `cat /tmp/gitleaks-camprompt.log`.
2. Настоящий секрет → убрать значение из файла. **Если он уже попал в коммит** — недостаточно удалить файл следующим коммитом: значение остаётся в истории, и для публичного репозитория его надо считать скомпрометированным (отозвать и заменить), а историю переписывать отдельной операцией.
3. Ложное срабатывание → добавить узкое правило в `.gitleaks.toml` (путь или конкретный regex), не отключая проверку целиком.
4. Файл вообще не должен быть в репозитории → в `.gitignore`.

Проверить репозиторий целиком вручную:

    gitleaks detect --source . --redact --no-banner          # вся история
    gitleaks detect --source . --no-git --redact --no-banner # рабочая папка

Хук не сработал вовсе (`.git/hooks/pre-commit` отсутствует — так бывает после клонирования):

    bash scripts/setup-git-hooks.sh

## 9. Отладка без живого Mac (для разработчика)

Единственный автоматический контроль — компиляция на CI. Порядок работы:

    # после правок
    git add -A && git commit -m "..." && git push origin main
    gh run watch <id> -R dminvest42-ui/camprompt --exit-status

    # предупреждения компилятора из зелёной сборки
    gh run view <id> -R dminvest42-ui/camprompt --log | grep -E 'warning:|error:' | grep -v Node.js

Чего CI **не** проверяет: геометрию панели, поведение TCC, цвета в светлой/тёмной теме, фокус ввода, курсоры, реальные камеры. Всё это — только чек-лист [RISKS](RISKS.md) §7 на живом Mac. Поэтому правки в этих зонах сопровождаются явным «что проверить» в ответе пользователю.

Проверка релиза:

    gh release view v0.2.2 -R dminvest42-ui/camprompt --json tagName,assets
