# Риски и ограничения CamPrompt

Навигация: [AGENT_ONBOARDING](AGENT_ONBOARDING.md) · [ARCHITECTURE](ARCHITECTURE.md) · [DECISIONS](DECISIONS.md) · [TROUBLESHOOTING](TROUBLESHOOTING.md) · [DEV_PLAN](DEV_PLAN.md) · [CHANGELOG](../CHANGELOG.md)

## 1. Ограничения macOS (неустранимые, заложены в дизайн)

| Ограничение | Влияние | Обход |
|---|---|---|
| Внутри notch нет пикселей (вырез матрицы) | Текст физически не может быть «в» notch | Чёрная панель вплотную под/вокруг notch визуально сливается с ним; глаза в 1-3° от объектива — этого достаточно |
| TCC-диалоги камеры/микрофона | Первый запуск требует 2 клика пользователя | Неустранимо (ОС); понятные usage descriptions на русском |
| Gatekeeper без нотарификации | Одна xattr-команда или «Открыть всё равно» при первом запуске | Устранится нотарификацией (M6, нужен Apple Developer аккаунт) |
| Mission Control скрывает оверлеи | Панель мигает при жесте | Системное поведение; `.stationary` смягчает |
| Меню-бар перекрывается панелью в её зоне | Пункты меню под панелью недоступны, пока она видна | Фича: сплошной чёрный «расширенный notch»; панель легко скрыть (Esc) |

## 2. Риск первого автономного релиза (главный)

Код собран в CI, но **ни разу не запускался на живом Mac** (kd-dev — Linux). Компиляция ≠ поведение: возможны сюрпризы в геометрии панели на конкретной модели MacBook, в порядке TCC-диалогов, в поведении SwiftUI-байндингов.

**Митигация:** все критические паттерны скопированы с работающих MIT-проектов (Textream 3.5k★ — панель; Peek — capture/бандлинг); v0.1 умышленно консервативен; первый запуск на живом Mac = smoke-тест, фиксы — тем же CI-циклом за минуты.

**Известные кандидаты на первые баги** (проверить при smoke):
1. Позиция панели на не-notch мониторе (fallback на main screen).
2. `TextEditor` binding при быстром наборе (сохранение на каждый keystroke).
3. Повторное открытие панели после Esc во время записи.
4. Переключение камеры во время записи (не блокируется в v0.1 — избегать).
5. HUD-hover поверх nonactivating панели (может требовать первый клик).

**Найдено в бою (2026-09-22, v0.1.2 → исправлено в v0.2.0; полный разбор — [DECISIONS D-011](DECISIONS.md#d-011-sessionpreset-выставляется-после-добавления-входов), [D-012](DECISIONS.md#d-012-отказ-входа-виден-пользователю-запись-не-стартует-без-видеосигнала)):** на одном из четырёх Mac встроенная камера «не включалась» при выданных разрешениях, а запись давала .mov только со звуком; айфоны через Continuity работали. Причина — не TCC, а порядок конфигурации `AVCaptureSession`: preset `.hd1920x1080` ставился ДО добавления входа, поэтому `canSetSessionPreset` (без входов) отвечал «да», а `canAddInput` для камеры 720p (MacBook Air M1, 13″ MacBook Pro) — «нет», и код это молча проглатывал. Теперь preset выбирается после входов (`.high` → 1080p только если камера умеет), отказ входа показывается пользователю, запись не стартует без живого видео-соединения, а в настройках камеры есть «Скопировать диагностику».

## 3. Производительность

| Риск | Вероятность | План Б |
|---|---|---|
| SwiftUI-рендер очень длинного текста (10k+ слов) при 60fps | Средняя | Одна Text-нода + offset уже минимизирует; далее — CATextLayer или разбивка на страницы |
| Превью+запись+скролл на Intel Mac | Низкая (рабочая машина на Apple Silicon) | Понизить preset до .high/720p |
| Timer 60Гц дрожит под нагрузкой | Низкая | CVDisplayLink/CADisplayLink (macOS 14) вместо Timer |

## 4. Совместимость

- macOS 14+ (Sonoma). Проверка `safeAreaInsets` — 12+, `.microphone`/`.external`/`.continuityCamera` device types — 14+, `ContentUnavailableView`/`onChange(two-param)` — 14+. На Mac без notch панель встаёт по центру верхней кромки — деградация мягкая.
- Xcode/SDK CI: раннер `macos-15` (Xcode 16.x, SDK macOS 15) при target 14 — штатно.

## 5. Хоткеи

Локальный NSEvent-монитор работает только когда CamPrompt — активное приложение. Если во время записи кликнуть в другое приложение, Пробел не поставит паузу. v2: KeyboardShortcuts (Carbon hotkeys, БЕЗ Accessibility-разрешения — в отличие от глобального NSEvent-монитора).

## 6. App Store (если пойдём)

- Sandbox: запись в ~/Movies потребует NSOpenPanel-выбора папки один раз (security-scoped bookmark) — UX-шаг.
- Review: window level `.screenSaver` и `sharingType=.none` — публичные API, прецеденты в Store есть (CueNotch, суфлёры). Риск отклонения низкий.
- `xattr`-инструкция не нужна в Store-версии.

## 7. Smoke-чеклист перед каждым релизом (5 минут на Mac)

1. .dmg открывается, приложение копируется и запускается (после xattr).
2. TCC-диалоги камера+микрофон появляются по одному разу.
3. Превью живое, зеркальность переключается.
4. «Показать суфлёр» → панель под notch, поверх Safari fullscreen.
5. Пробел/R/↑↓/Esc работают.
6. Запись: countdown → красный таймер → стоп → файл в ~/Movies/Teleprompter, открывается, звук есть.
7. Настройки текста применяются live и переживают перезапуск.
8. Скрипты: создание/редактирование/удаление, выживают перезапуск.
9. Луп-режим зацикливает.
10. «Прятать от записи экрана» — панель исчезает из QuickTime-записи экрана.
11. Второй монитор: панель на notch-экране.
12. Cmd+Q — чистое завершение (запись остановлена и сохранена).
13. На Mac с камерой 720p (Air M1 / 13″ Pro): превью живое, в Камера → «Сигнал» видно `1280×720 · High`, запись содержит видео.
14. Края панели: курсор меняется на ↔ / ↕, перетаскивание меняет ширину/высоту, значение попадает в ползунки настроек и переживает перезапуск.
15. Поле с числом у ползунка: ввод `20` + Enter даёт ровно 20; ввод вне диапазона обрезается до границы.
16. Поповеры «Текст» и «Суфлёр» открываются мгновенно (v0.2.0 открывались секунды: `Slider(step:)` на macOS рисует засечку на каждый шаг — 1300 штук для ширины; с v0.2.1 шаг снапится в Binding, без `step:` — [D-013](DECISIONS.md#d-013-шаг-ползунка--в-binding-а-не-в-sliderstep)).
17. Плашка на суфлёре тёмная, все кнопки различимы **в светлой системной теме тоже** ([D-015](DECISIONS.md#d-015-фон-плашки-управления--сплошной-тёмный-не-ultrathinmaterial)).
18. Скорость на плашке: клик по числу → ввод `20` + Enter → едет со скоростью 20; кнопки ± меняют на 1; пробел и стрелки во время ввода уходят в поле, а не в суфлёр ([D-014](DECISIONS.md#d-014-панель-может-становиться-key-оставаясь-неактивирующей), [D-017](DECISIONS.md#d-017-кнопки--на-плашке-шагают-по-1)).
